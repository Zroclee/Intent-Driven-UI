## 1. 背景与现状

### 1.1 现状分析

当前，我们面对的是一个深耕多年、承载大量定制化业务场景的业务中台系统。在对该系统进行AI赋能的过程中发现，纯文本的AI交互模式在体验上远不如现有成熟业务系统直观高效。因此，我们亟需引入一种全新的交互模式——通过AI识别用户意图，动态驱动对应的业务组件进行展示，从而推动交互方式从传统的鼠标操作向“AI驱动”的界面转变，实现AI与现有业务场景的深度结合。

在AI应用开发中，交互体验的“最后一公里”至关重要，它是将AI的“智慧”转化为用户“所见”的关键环节。若此处衔接不畅，即使意图识别再准确，整体体验也会大打折扣。

### 1.2 痛点与瓶颈

在当前的AI交互模式下，我们主要面临以下核心瓶颈：

- **交互体验割裂：** 成熟的图形化业务逻辑与纯文本对话模式难以有机融合。用户在进行复杂业务操作时，AI的辅助效率与体验远不及传统业务系统，造成明显的体验断层。

- **赋能方式零散：** 目前的AI能力改造多为垂直场景下的单点突破，缺乏一套标准化、可复用、能贯穿不同业务的系统性驱动架构。

- **多模态能力局限：** 现有大模型在文本生成、数据准确性、图表渲染及响应速度等方面仍存在不足，其多模态能力尚不足以直接替代现有成熟、精准的业务可视化界面。


## 2. 通用AI方案

针对上述痛点，我们设计了两套通用AI解决方案，分别面向不同层级的用户需求：

1. 产品助手：面向所有用户，旨在帮助其快速理解产品功能，提供页面跳转与操作指引。

2. 业务助手：面向特定业务场景的专家，旨在辅助其进行数据分析与决策，并实时联动业务数据组件，验证分析结果。

### 2.1 产品助手
此方案旨在通过智能体（Agent）理解并操控我们的产品或业务系统。用户可使用自然语言指令，由AI识别意图、加载对应业务页面，并提供场景介绍、数据分析等交互服务。

其核心挑战在于：如何让大语言模型（LLM）准确理解自然语言，并以此可靠地操控结构化的业务系统，实现双向、连贯的交互。

#### 2.1.1 核心设计理念

在本架构中，AI不再是一个孤立的对话工具，而是升级为系统的**智能中枢**.

1. **意图识别：** 将用户口语化请求（如“我想查看车辆数据”）精准转化为可执行的系统指令。
 
2. **语义路由：** 摒弃固定的硬编码菜单逻辑，构建“页面/功能向量索引”，由AI动态决策并导航至目标界面。

3. **双向通信：** 前端不仅接收AI指令进行跳转，还需将当前页面的结构化数据快照同步给AI，为其提供持续的分析上下文，形成交互闭环。


### 2.2 业务助手

此方案旨在深度赋能业务专家，针对特定场景进行数据分析与决策。AI不仅依据业务逻辑与行业规则提供专业判断与建议，还能在对话过程中，实时、动态地渲染对应的数据可视化组件，为业务决策提供直观的数据参考与验证依据。

其核心挑战在于：如何在连续的对话流中，实时识别业务数据意图，并动态加载、渲染正确的业务组件。

#### 2.2.1 核心设计理念

在本架构中，AI助手超越了文本分析，成为能够直接驱动数据视图的**智能协作者**。

1. **意图驱动视图：** 前端视图的渲染完全由AI对话实时生成的结构化业务数据所驱动，实现真正的“所言即所得”。

2. **约定优于配置：** 通过标准化的数据契约（如MCP协议），严格约定AI输出与前端组件所需的接口，确保数据与视图的精准、无缝对接。

3. **组件原子化：** 每个业务组件被设计为功能独立、接口标准的原子单元，保持高内聚与低耦合，通过统一的属性（props）接口被AI灵活调用与组合。

4. **异步加载与性能优化：** 采用异步加载与代码分割技术，确保仅在AI触发特定业务场景时，才动态加载对应的组件代码包，从而保障系统的整体性能与响应速度。


## 3. 架构设计

在架构设计之初，我们确立了核心目标：构建一套能够快速适配各类业务场景的通用AI应用架构。为确保其长期生命力与广泛适用性，我们严格遵循以下设计原则：

*   **通用性 (Universality)**：核心架构与业务逻辑解耦。系统通过大模型的语义理解能力进行任务分发，而非硬编码业务规则，确保架构可跨业务线复用。
*   **模块化 (Modularity)**：采用“原子化”设计。每个智能体（Agent）和工具（Tool）都是独立的模块，支持独立开发、测试、热插拔。
*   **可扩展性 (Scalability)**：遵循“微内核，富生态”理念。通信总线和调度中枢保持轻量，通过增加 Plugin（工具）和 Agent（智能体）来扩展系统能力边界。
*   **安全性 (Security)**：构筑“人机协同”安全防线。在关键指令执行链路中嵌入审批与校验模块，建立明确的数据隐私与操作安全围栏。

### 3.1 业务助手架构设计

业务助手架构的核心是实现由对话意图实时驱动UI组件渲染。其设计需聚焦于三个关键层面：
1. **数据与逻辑层：** 集成特定业务场景的数据获取工具，并内嵌蕴含行业规则与业务逻辑的提示词工程，确保AI分析的专业性。

2. **解析与驱动层：** 设计稳健的协议（如MCP），用于将AI输出的结构化数据精准映射到对应的原子化业务组件。

3. **渲染与性能层：** 前端采用动态加载机制，根据AI指令按需加载并渲染组件，同时保障应用的响应性能与用户体验。

### 3.2 产品助手架构设计
产品助手架构旨在实现应用级的智能导航与操控。其设计需解决页面识别、跨应用通信与上下文管理等问题：

1. **页面识别与路由：** 利用微前端、iframe等技术动态加载目标页面，并建立“自然语言-页面路由”的语义索引，实现精准跳转。

2. **上下文获取与管理：** 提供标准化的应用间通信机制，通过渐进式披露的方式使AI能够提取并理解当前页面的关键数据与状态，形成连续对话的上下文。

3. **技能与服务化：** 将页面导读、功能解说等能力封装为标准化技能，供AI智能体灵活调用，实现从导航到讲解的端到端辅助。
